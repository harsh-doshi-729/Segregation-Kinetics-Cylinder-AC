This directory contains scripts and files relating to the simulations performed for checking whether a mixed state of polymers has concantenated polymers or not.
Polymers are said to be concantenated if they are interlocked with one another or if their subloops are interlocked with one another.
Such a state of polymers has an additional topological constraint that might affect their segregation kinetics, and hence we do not want out polymers to be concatenated.

In this directory, the following scripts should be run one after the other to check for concatenations in the mixed state created in the Create_Initial_States/ directory:
i) Check_Concatenation/Scripts/copyShrinkExecute.sh
ii) Check_Concatenation/Scripts/predict_concatenation.sh

The function of the scripts in the Scripts/ folder are explained below:

copyShrinkExecute.sh:
Copies the last snapshot (mixed state) of the shrink-relax simulation performed in the Create_Initial_States/ directory to a corresponding subdirectory within Check_Concatenation/. 
It then runs simulation(s) starting from the mixed state to determine whether the polymers are concantenated. It uses the two LAMMPS scripts mentioned below.

predict_concantenation.sh:
Uses the output generated by the previous simulation and the predict_concatenation.c script to give a yes/no answer for whether the particular mixed state has concatenated polymers.

segregate.lammps:
Runs a LAMMPS simulation to check whether the two polymers are concantenated.

separate_segregate.lammps:
Runs LAMMPS simulations for each of the two polymers in the mixed state to check whether they have concantenations between their internal loops.

Each of these bash scripts takes certain arguments from the command line when they are run. If they are run without any arguments, they will display a message explaining what arguments should be passed. Most arguments should be self-explanatory.
A special argument for some of these scripts is a 'flag' that indicates whether the polymers should be checked for internal concatenations.
This should be true (or 1) when there are multiple loops present in the architecture (such as Arc-1-2, Arc-1-5, and Arc-1-10).
In this case, the scripts will check for concatenations between any such pair of closed loops in addition to checking for concatenations between the polymers. 
For all other architectures that do not require checking internal concatenations, the flag should be false (or 0).

Once done, the output of the predict_concatenations.sh writes the verdict to a file 'concantenations.txt' in the parent folder to the simulation files. This file contains entries for each run that was tested and can either be something like: 'The polymers segregated at <time>' or "The polymers are concatenated?'.
It should be noted that if the latter message is displayed, it is not conclusive that the polymers are concatenated.

All of the scripts can also be run individually (manually) if desired.
The usage for the two LAMMPS scripts is given below:
$ lmp -in /path/to/segregate.lammps -var numberOfMonomers <number> -var seed <seed>
$ lmp -in /path/to/separate_segregate.lammps -var numberOfMonomers <number> -var polymerIndex <index> -var seed <seed>
In the latter script, the polymerIndex is a variable that indicates which of the two polymers should be selected. The value can be 1 or 2.

Once the user is satisfied that there are no concatenations in the mixed state, they can proceed to the segregation simulation performed in Segregation/.
